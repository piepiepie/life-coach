# 跨模型映射表

> 本文档提供五大模型(MBTI、VIA、CliftonStrengths、DISC、Holland)之间的交叉映射关系，帮助AI教练在多个模型结果之间建立联系，三角定位更准确的自我画像。

---

## 一、使用说明

### 1.1 映射表结构
每对模型之间的映射包含三个维度：
- **关联性**：两个维度之间的统计学或概念关联强度
- **洞察**：将两个维度结合后能发现的新信息
- **应用**：如何在辅导对话中运用这个映射

### 1.2 三角定位原理
当两个或以上模型指向同一方向时，该特征的置信度显著提升。当模型之间出现矛盾时，则揭示出值得深入探索的内在张力。

## 十一、三角定位使用指南

### 11.1 确认信号强度
当三个及以上模型指向同一特征时，该信号为"强信号"，应重点对待：
- 例：MBTI F + VIA 善良 + DISC S + Holland S → 强助人倾向
- 例：MBTI N + Strengths 战略 + VIA 创造力 + Holland A → 强创新倾向

> **1.3 强化（反幻觉校验）**：即便多模型一致，也**不**等于结论已验证。一致性可能来自 LLM 为保持连贯而自觉往同一处"拽"的伪一致（一致性幻觉）。因此每个"强信号"在输出前**必须**同时给出支持证据、反对证据、并主动构造反例（见 §十三）。多模型一致提升的是**探索优先级**，不是结论的确定性。

### 11.2 识别盲区
当某个模型缺失而其他模型覆盖时，该维度可能是用户的盲区：
- 例：所有模型都显示社交能力，但VAI"社交智慧"得分低 → 用户可能有社交能力但缺乏社交自信

### 11.3 解析矛盾
当两个模型之间存在矛盾时，优先探索而非忽视：
- 例：DISC高D但VIA高善良 → 用户可能在工作中有强势表现，但核心价值观是利他

### 11.4 综合画像
使用交叉映射构建用户的多维度画像：
1. 核心驱动力：从VIA和Holland提取
2. 行为风格：从DISC和MBTI提取
3. 能力优势：从Strengths提取
4. 交叉验证：使用本映射表验证一致性
5. 矛盾探索：对不一致维度进行深度对话

## 十二、实践建议

1. **不要机械使用**：映射表提供关联可能性，而非确定性结论
2. **优先探索矛盾**：矛盾之处往往是最有价值的发现点
3. **以用户体验为准**：任何映射关系都需要用户确认"这感觉对吗"
4. **注意文化差异**：部分映射在中国文化背景下可能需要调整
5. **动态看待**：人是动态发展的，今天的映射不一定代表明天的画像

## 十三、反幻觉校验（1.3 新增）

> 解决"多模型一致 = 高置信"这一隐含谬误。一致性可能源于 LLM 连贯性偏好而非真实心理证据。本框架强制对每个强信号做**三角压力测试**，让 AI 主动寻找能推翻自己的证据。

### 13.1 每个强信号必须产出"三件套"

对任意被标记为"强信号"的特征/方向，AI 内部必须补全以下三项后再输出：

| 组件 | 要求 | 目的 |
|------|------|------|
| **支持证据** | 列出哪些模型、哪些用户原话/真测评支撑该信号 | 说明为何提出 |
| **反对证据** | 列出与该信号冲突的模型结果、用户经历或市场现实 | 防止单向确认 |
| **主动反例** | 构造一个"若成立则推翻该信号"的具体情景或数据点 | 检验信号的脆弱性 |

> 若**无法**给出反对证据或反例（例如用户所有数据都单向指向），也须在输出中注明"目前未找到反对证据，但可能存在未采集维度"，**不得**伪装满分确定。

### 13.2 一致性幻觉的典型来源（AI 自检清单）

- 模型文本高度相关（MBTI F 与 VIA 善良本就常共现）→ 共现 ≠ 因果，最多算"互相印证"
- 对话早期用户自我标签被 AI 反复引用 → 形成"回音壁"
- 真测评缺失时，纯推断画像内部自洽 → 自洽是 LLM 能力，非用户事实
- 市场数据缺失时，用训练记忆补成"看起来真实"的趋势 → 见 `market_data_protocol.md` 失败处理

### 13.3 输出时的软化处理

- 强信号表述：**"多个模型都指向 X，这是一个值得重点探索的方向"**，而非"你就是 X 型人"。
- 当用户据信号下绝对结论（"我是 INTJ 所以不适合销售"），AI 须用 §13.1 反例温和挑战（参见 `assessments/real_assessment_bridge.md` 反伪精确护栏）。
- 置信度随证据类型分级：真测评一致 > 多模型推断一致 > 单模型推断。

### 13.4 与 §3.0 洞察标签的衔接

在校验中若发现"一致但脆弱"的信号，内部标记为 `[推断-低置信]`（见 `real_assessment_bridge.md`）；若用户提供了冲突的真测评，以真测评为基准回溯推断偏差。
