# 真实市场数据接入协议（Market-Intelligence Protocol）

> 本文档解决原技能两大短板：① 职业映射"类型→领域"的刻板性；② 缺真实市场/招聘数据，落地步骤靠大模型临场生成易空泛。
> 目标：把"你的画像"与"市场现实"对接，产出**差距分析 + 现实路径**，而不是一份匹配清单。

---

## 一、何时触发（触发条件）

当对话进入以下任一节点时，AI **必须**先尝试拉取真实市场数据，再给方向：

1. 用户主动问："我能做哪个行业/角色？""这个方向现在还有机会吗？"
2. 场景模拟模式（转行/创业/换城市）已确定目标方向
3. 交叉分析输出"强信号方向"后，需要验证该方向的市场可行性
4. 资源推荐模式需要给出"第一步具体动作"时

**不触发**：纯自我认知/陪伴对话阶段（L1–L3、创伤陪伴、信念探索），不在此阶段打扰用户。

---

## 二、拉取什么（数据字段）

每个目标方向，至少覆盖以下字段（能拿到几个拿几个，**拿不到就明说拿不到，绝不编造**）：

| 字段 | 说明 | 示例 |
|------|------|------|
| **职责门槛** | 该岗位核心职责 + 硬门槛（学历/证书/技能） | 用户研究员：需用户研究/访谈/可用性测试经验，常用 Figma、问卷工具 |
| **薪资区间** | 按城市/经验分位的区间 | 上海 1–3 年：12k–22k/月 |
| **需求趋势** | 增长 / 平稳 / 萎缩 + 依据 | AI 产品经理：2024–2026 持续扩张 |
| **地域分布** | 机会集中城市 | 北京/上海/深圳/杭州为主 |
| **典型雇主** | 代表公司/赛道 | 大厂、AI 独角兽、咨询公司 |
| **入行路径** | 转行者常见的 3 条切入方式 | 运营转→先做用户研究 side project→作品集→内推 |

---

## 三、怎么拉（执行规范）

1. **用 WebSearch / WebFetch**：以"岗位名 + 城市 + 招聘 / 薪资 / 前景 / JD"为中文查询词。
2. **多源交叉**：至少 2 个来源（招聘平台、行业报告、薪资调研、职场社区），避免单一信源偏差。
3. **标注时效**：每条数据后附 `(来源：X，检索于 YYYY-MM-DD)`。
4. **失败处理**：若搜索无果或结果矛盾，**明确告知"未能获取可靠市场数据，以下方向仅为画像推断"**，不得用训练记忆补足成"看起来真实"的数字。
5. **概率表述**：所有市场结论用"目前来看 / 多数岗位要求 / 趋势显示"，不用"一定 / 肯定"。

---

## 四、产出格式（市场现实卡）

```
【市场现实卡 · <方向名>】  检索于 YYYY-MM-DD
- 职责门槛：…
- 薪资区间（<城市>）：…
- 需求趋势：↑增长 / →平稳 / ↓萎缩（依据：…）
- 地域机会：…
- 典型雇主：…
- 转行常见切入：①… ②… ③…
- 数据置信度：高 / 中 / 低（说明：…）
- 注意：以上为公开信息聚合，非承诺，需结合个人情况验证。
```

---

## 五、与原有流程的衔接

- 本卡**插入 AQAL 安放（LR 它们 象限）之后**，作为"天赋落地"的现实校验层。
- 与 `career_mapping.md`、`career_database.md` 的关系是：**模型给"可能方向"，本卡给"市场现实"，二者对照得出差距**。
- 若模型方向与市场现实冲突（如模型指向"传统纸媒编辑"，市场显示萎缩），AI 应主动提示并建议相邻方向。

---

## 六、护栏

- 不提供"保offer""包上岸"类承诺。
- 数据有时效，每次关键决策前建议重新检索（可结合发展追踪模式定期刷新）。
- 本卡是辅助信息，最终决策权在用户。

---

## 七、降级处理（无联网 / 无 WebSearch·WebFetch 环境）

当运行环境**不具备联网检索能力**时，必须降级，不得假装拉到了数据：

1. **跳过拉取**：不进入 §三 的 WebSearch/WebFetch 流程，直接判定"市场现实卡：不可用"。
2. **明确告知**：向用户输出一句明示——"⚠️ 当前环境未接入市场数据，以下方向仅为**画像推断**，未经验证，请自行到招聘平台/行业报告核实后再决策。"
3. **不编造**：严禁用训练记忆补出"看起来真实"的薪资/趋势数字；涉及市场事实时统一用"我无法实时核实"替代。
4. **保留画像价值**：降级后，天赋排序、职业映射、Playbook 仍可正常使用——只是缺"市场现实层"校验；可提示用户"先按方向行动验证，联网后再补市场卡"。
5. **探测提示**：若环境在某次对话中突然可用（或用户自己粘贴了检索结果），按 §三–§五 正常流程补卡，并标注"数据由用户/环境提供，检索于 YYYY-MM-DD"。

> 与 `integrated_item_bank.md` §7.2 衔接：题型库排序后若触发本协议的"有联网"分支则拉卡校验；若命中本 §七 降级分支，则跳过并提示用户核实。
