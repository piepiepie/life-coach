# 行业落地 Playbook 模板

> 解决原技能"有方向框架、缺血肉"的问题。每个高频方向配一份可执行的落地手册，让"1 个月 / 3 个月行动"从临场发挥变成有结构的具体步骤。
> 本文件是**模板 + 8 个已填方向**（用户研究、内容策略、产品运营、AI 产品、UX 设计、数据分析、自由职业/自媒体、ESG/可持续）。新增方向按"标准结构"补充即可；市场数据以 `market_data_protocol.md` 实时校验为准。

## 二、示例：用户研究员（User Researcher）

### 1. 能力门槛
- 硬：用户访谈、问卷设计、可用性测试、基础数据分析；工具 Figma/Figjam、问卷星/Maze、Excel/SQL。
- 软：共情倾听、把模糊需求转成洞察、用证据说服产品/设计。

### 2. 3 个月学习路径
- 第 1–2 周：读《用户体验度量》《About Face》前 3 章；看 3 个完整用户访谈录像。
- 第 3–4 周：自己设计一份 10 题访谈提纲，找 3 位朋友做真实访谈并整理成洞察笔记。
- 第 5–8 周：做一个完整小项目（选一个你熟悉的产品，做 5 人可用性测试 + 1 份报告）。
- 第 9–12 周：把项目做成作品集网页；在现岗位主动争取 1 个用户研究 side project；开始约 3 位从业者信息访谈。

### 3. 信息访谈清单
1. 你一天典型在做什么？和入职前想的一样吗？
2. 这个岗位最反直觉的一点是什么？
3. 招人时最看重什么证据——作品集还是经历？
4. 你是怎么入行的？转行前在做什么？
5. 哪类人在这个岗位容易卡住？
6. 业务方（产品/设计）最常在哪和你冲突？怎么解决？
7. 如果重来，你会提前练什么？
8. 未来 2 年这个岗位会被 AI 怎么改变？

### 4. 作品集方案
- A：把"5 人可用性测试报告"做成图文网页（含方法、原始引语、结论、建议）。
- B：写 3 篇"我访谈了 N 个用户后发现的 X"短文，发在即刻/公众号/小红书。

### 5. 常见坑
- 只做访谈不沉淀洞察 → 要能说出"所以产品该改什么"。
- 把"用户说"当"用户要" → 区分陈述与真实行为。
- 没有量化意识 → 至少学会用基础数据支撑结论。

### 6. 验证里程碑
- 1 个月：完成 3 次真实访谈 + 1 份洞察笔记，有人反馈"有用"。
- 3 个月：作品集网页完成 + 至少 1 次信息访谈得到"你这方向可行"的确认。

## 三、内容策略（Content Strategist）

### 1. 能力门槛
- 硬：选题、文案、分发数据、SEO/关键词、基础排版；工具 飞书/Notion/公众号后台/新榜/5118。
- 软：用户洞察、把复杂讲简单、数据驱动的选题迭代。

### 2. 3 个月学习路径
- 第 1–2 周：读《内容引力》《疯传》；拆 10 个标杆账号的选题结构。
- 第 3–4 周：起一个个人号，发 20 篇并逐篇记阅读/涨粉/转发数据。
- 第 5–8 周：做 1 篇爆款拆解 + 数据复盘报告（选题—数据—迭代假设）。
- 第 9–12 周：把复盘做成作品集网页；约 3 位从业者信息访谈。

### 3. 信息访谈清单
1. 你一天典型在做什么？和入行前想的一样吗？
2. 这个岗位最反直觉的一点是什么？
3. 招人时最看重作品集还是经历？
4. 你是怎么入行的？转行前在做什么？
5. 哪类人容易在这个岗位卡住？
6. 和数据/增长团队怎么配合？
7. 你们的 KPI 怎么定、怎么背？
8. 未来 2 年这个岗位会被 AI 怎么改变？

### 4. 作品集方案
- A：账号成长复盘页（选题—数据—迭代）。
- B：爆款拆解报告（含方法论）。

### 5. 常见坑
- 追热点无定位 → 先定人群再追形式。
- 只看阅读不看转化 → 关注转发/收藏/涨粉。
- 不建分发矩阵 → 单平台风险高。

### 6. 验证里程碑
- 1 个月：发满 20 篇，有 1 篇明显高于均值。
- 3 个月：复盘报告被从业者认可"方向可行"。

## 四、产品运营（Product Operations）

### 1. 能力门槛
- 硬：用户增长、活动策划、数据分析、埋点、AB 测试；工具 神策/GrowingIO/SQL/飞书。
- 软：跨团队推动、目标拆解、用数据讲故事。

### 2. 3 个月学习路径
- 第 1–2 周：读《增长黑客》《运营之光》。
- 第 3–4 周：完整复盘一个活动（目标—动作—结果—归因）。
- 第 5–8 周：学 SQL 到能写多表 join + 窗口函数，做真实数据集的漏斗分析。
- 第 9–12 周：作品集网页 + 约 3 位从业者访谈。

### 3. 信息访谈清单
1. 你背什么指标？怎么拆解到周？
2. 最反直觉的一点是什么？
3. 招人最看重什么证据？
4. 你是怎么入行的？
5. 哪类人容易卡住？
6. 和业务方目标不对齐时怎么处理？
7. 埋点谁定、数据可信吗？
8. AI 对你的工作改变最大的是什么？

### 4. 作品集方案
- A：活动复盘报告（假设—动作—数据—结论）。
- B：数据看板截图 + 业务解读。

### 5. 常见坑
- 只做执行不背指标 → 运营要对结果负责。
- 不懂埋点 → 数据不可信，决策失真。
- 和业务方目标不对齐 → 白忙。

### 6. 验证里程碑
- 1 个月：能独立写 SQL 取数并出一份漏斗分析。
- 3 个月：活动复盘被认可"逻辑清楚"。

## 五、AI 产品（AI Product Manager）

### 1. 能力门槛
- 硬：需求分析、PRD、模型基础认知（LLM/RAG/微调边界）、数据闭环、基础 SQL + 能读 Python。
- 软：把技术能力翻译成用户价值、和算法/工程对话、管理预期。

### 2. 3 个月学习路径
- 第 1–2 周：读《AI 产品经理》；用 API 跑通一个小 demo（如摘要/问答）。
- 第 3–4 周：写一个 AI 功能的 PRD（含评测指标与边界）。
- 第 5–8 周：做一个 prompt/agent 小项目并测效果（准确率/满意度）。
- 第 9–12 周：作品集 + 约 3 位 AI PM 访谈。

### 3. 信息访谈清单
1. 你一天在和谁对话最多（算法/工程/业务）？
2. 最反直觉的一点是什么？
3. 招人最看重模型认知还是业务认知？
4. 你是怎么入行的？
5. 哪类人容易卡住？
6. 怎么和算法对齐预期、避免瞎承诺？
7. 评测怎么做、谁来定标准？
8. 这个岗位 2 年后还需要人吗？

### 4. 作品集方案
- A：AI 功能 PRD + 评测方案。
- B：自己做的 agent demo 录像 + 效果数据。

### 5. 常见坑
- 不懂模型边界瞎承诺 → 翻车。
- 只做功能不懂数据闭环 → 上不了线也优化不了。
- 不会和算法对齐预期 → 来回返工。

### 6. 验证里程碑
- 1 个月：能跑通一个 API demo 并讲清能力边界。
- 3 个月：PRD + demo 被从业者认可"懂行"。

## 六、UX 设计（UX Designer）

### 1. 能力门槛
- 硬：用户研究、信息架构、交互稿、可用性测试、设计系统；工具 Figma/Figjam/Prott。
- 软：共情、把模糊需求结构化、用原型低成本验证。

### 2. 3 个月学习路径
- 第 1–2 周：读《简约至上》《设计心理学 1》。
- 第 3–4 周：临摹 3 个 App 关键流程并重做一版。
- 第 5–8 周：做完整项目（访谈 + 架构 + 高保真 + 测试）。
- 第 9–12 周：作品集网页 + 约 3 位设计师访谈。

### 3. 信息访谈清单
1. 你一天在做什么？和入行前想的一样吗？
2. 最反直觉的一点是什么？
3. 招人最看重过程还是视觉？
4. 你是怎么入行的？
5. 哪类人容易卡住？
6. 和业务/产品冲突最多的是哪？
7. 你的设计决策怎么讲清楚？
8. AI 设计工具改变了什么？

### 4. 作品集方案
- A：完整项目页（过程 > 结果）。
- B：可用性测试视频片段。

### 5. 常见坑
- 只画界面不碰研究 → 决策无依据。
- 炫技不解决真问题 → 评审过不了。
- 没有设计决策理由 → 显得"美工"。

### 6. 验证里程碑
- 1 个月：完成 3 次真实访谈 + 1 份洞察。
- 3 个月：作品集被认可"有思考"。

## 七、数据分析（Data Analyst）

### 1. 能力门槛
- 硬：SQL / Python（或 R / Excel）、可视化、统计基础、业务理解；工具 Tableau/PowerBI/BI 平台。
- 软：把业务问题转成可分析问题、用图表讲清楚、怀疑数据质量。

### 2. 3 个月学习路径
- 第 1–2 周：学 SQL 到能写多表 join + 窗口函数。
- 第 3–4 周：做一个公开数据集的 EDA（探索性分析）。
- 第 5–8 周：做一个带业务结论的看板 + 报告。
- 第 9–12 周：作品集 + 约 3 位分析师访谈。

### 3. 信息访谈清单
1. 你一天在做什么？
2. 最反直觉的一点是什么？
3. 招人最看重 SQL 还是业务感？
4. 你是怎么入行的？
5. 哪类人容易卡住？
6. 数据口径不一致时怎么处理？
7. 怎么让业务方信你的结论？
8. AI/BI 工具替代了哪些活？

### 4. 作品集方案
- A：看板截图 + 业务解读。
- B：EDA 报告（问题—方法—结论—建议）。

### 5. 常见坑
- 只会取数不会解读 → 沦为"人肉 SQL"。
- 不校验数据口径 → 结论错。
- 和业务方需求脱节 → 做了没人用。

### 6. 验证里程碑
- 1 个月：能独立出一份带业务结论的看板。
- 3 个月：报告被认可"讲清楚了"。

## 八、自由职业 / 自媒体（Freelance / Creator）

### 1. 能力门槛
- 硬：一项可交付的专业能力（设计/写作/开发/咨询）+ 自我营销、报价、合同、交付管理。
- 软：自驱、抗不确定、持续产出、客户沟通。

### 2. 3 个月学习路径
- 第 1–2 周：明确 niche（别什么都接）+ 做作品首页。
- 第 3–4 周：在平台（小红书/即刻/闲鱼/猪八戒）发 10 条专业内容获首批线索。
- 第 5–8 周：接 1–2 个真实小单，跑通"需求—报价—交付—回款"。
- 第 9–12 周：建标准报价单 + 复盘获客渠道 ROI。

### 3. 信息访谈清单
1. 你靠什么获客？占比最高的是哪个？
2. 最反直觉的一点是什么？
3. 你怎么定价的、被压价过吗？
4. 你是怎么开始的？
5. 哪类人容易撑不下去？
6. 怎么管理现金流和空窗期？
7. 复购率怎么提？
8. 如果重来你会先准备什么？

### 4. 作品集方案
- A：个人主页（作品 + 案例 + 报价）。
- B：一篇"我是怎么做 X 的"方法论文。

### 5. 常见坑
- 不聚焦什么都接 → 不成专家。
- 不会定价 → 被压价还累。
- 没现金流规划 → 空窗期慌。
- 忽视复购 → 一直找新客。

### 6. 验证里程碑
- 1 个月：拿到首批真实线索。
- 3 个月：跑通 1–2 单完整交付 + 有标准报价单。

## 九、ESG / 可持续（ESG / Sustainability）

### 1. 能力门槛
- 硬：ESG 框架（GRI/SASB/TCFD）、碳核算基础、报告撰写、政策跟踪、数据收集；工具 Excel/碳核算软件/Wind。
- 软：跨部门协调、把合规讲成价值、中英文报告。

### 2. 3 个月学习路径
- 第 1–2 周：读 GRI 标准 + 一份上市公司 ESG 报告。
- 第 3–4 周：做一个行业 ESG 现状梳理。
- 第 5–8 周：参与或模拟一个碳排 / 社会责任项目。
- 第 9–12 周：作品集 + 约 3 位从业者访谈。

### 3. 信息访谈清单
1. 你一天在做什么？
2. 最反直觉的一点是什么？
3. 招人最看重框架还是业务？
4. 你是怎么入行的？
5. 哪类人容易卡住？
6. 数据口径不统一时怎么处理？
7. 怎么把合规讲成商业价值？
8. 政策波动大，怎么保持方向？

### 4. 作品集方案
- A：ESG 报告节选 / 分析。
- B：行业梳理长文。

### 5. 常见坑
- 只懂框架不懂业务 → 落不了地。
- 数据口径不统一 → 不可比。
- 当成纯合规 → 忽视商业价值。

### 6. 验证里程碑
- 1 个月：能独立梳理一个行业 ESG 现状。
- 3 个月：报告/分析被认可"专业"。

## 十、使用方式

- 当用户方向落入某 Playbook 覆盖的方向时，AI 读取对应 Playbook，结合**用户现实约束**（城市/资本/可投入时间/家庭阶段）做裁剪后给出。
- Playbook 是**起点不是终点**：AI 应鼓励用户用信息访谈验证，并随市场变化更新内容。
- 未覆盖的方向：AI 按"标准结构"临时生成一份精简版，并标注"此份为即时生成，建议进一步验证"。
